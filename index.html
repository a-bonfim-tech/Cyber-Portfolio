Featured Lab

Vision Base64 Security Lab — AI Portraits Case Study

This lab is an authorial security-focused case study based on the Google Cloud Skills Boost lab “Detect Labels, Faces, and Landmarks in Images with the Cloud Vision API (GSP037)”, but with a twist: instead of repeating a tutorial, I redesigned it as a security artifact.

Scope & Objectives
Goal: Process AI-generated portraits with Vision API while treating them as sensitive data and embracing errors as part of the design.
  • Use three AI-generated self-portraits as private, local inputs.
  • Convert them into Base64 and build manual JSON requests for LABEL + FACE detection.
  • Authenticate using Application Default Credentials (ADC) and OAuth2 tokens.
  • Call vision.googleapis.com and capture real 403 PERMISSION_DENIED errors.
  • Explain why those errors happen (quota project, service enablement, IAM) and how to fix them.
Vision API Base64 workflow OAuth2 · ADC 403 analysis STRIDE Cloud Shell

The value of this lab is not “everything worked perfectly”. It is how I reasoned when the platform pushed back.

Security Reasoning

Threat Modeling & Data Handling

I applied the STRIDE model to think about how this workflow could fail or be abused.

  • Spoofing: only OAuth2 ADC tokens from gcloud are used — no API keys.
  • Tampering: JSON requests are generated from controlled files and scripts.
  • Repudiation: error responses are stored under /responses as an audit trail.
  • Information Disclosure: raw portraits are never committed; only placeholders are stored.
  • Denial of Service: quota/403 errors are documented and connected to ADC/quotas.
  • Elevation of Privilege: no long-lived secrets or over-privileged service accounts.

This mindset — using errors and constraints as learning signals — is what I want to bring to a security team.
